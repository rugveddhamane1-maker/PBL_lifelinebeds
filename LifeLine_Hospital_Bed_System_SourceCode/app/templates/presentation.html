Problem Statement & Motivation

The Critical Care "Golden Hour" Delay

Existing Reality

During acute medical emergencies (severe trauma, cardiac arrest, respiratory distress, neonatal crisis), patients and ambulance attendants lose 35 to 50 critical minutes traveling to hospitals that are already 100% occupied.

  • • Emergency phone lines are frequently busy during peak hours.
  • • Static hospital websites display stale data that is hours or days old.
  • • Zero coordination between hospital triage casualty desks and citizens.
The LifeLine Solution

A centralized, event-driven web portal that provides live, granular visibility into ICU, NICU, Ventilator, Oxygen, and General ward beds.

  • • Casualty staff update bed statuses with a single touch from any smartphone or tablet.
  • • Delta broadcasts across the entire city network in under 50 milliseconds.
  • • 1-Click direct ambulance casualty SOS and GPS navigation route.
High-Level Architecture

End-to-End System Pipeline

1. Client Tier (Presentation)

Mobile-first responsive interface built with Tailwind CSS & FontAwesome. Includes Patient Search, Staff Touch Counters, and City Surveillance Analytics.

2. Application & WebSocket Hub

High-performance asynchronous Python FastAPI backend. Central ConnectionManager maintains persistent WebSocket tunnels for sub-50ms push notifications.

3. SQL Relational Database

SQLAlchemy 2.0 ORM with relational integrity. Enforces strict schema constraints, negative bed protection, and permanent shift audit logging.

Engineering Innovation

Why WebSockets? Eliminating the "Polling Trap"

Traditional HTTP Polling (Flawed)

Clients repeatedly query the server every 5 seconds even when 99% of requests return unchanged data.

GET /api/beds (no change)
GET /api/beds (no change)
GET /api/beds (no change)
→ 60,000 redundant requests/min for 1000 users!

LifeLine Event-Driven WebSocket (Optimal)

A single, persistent bi-directional TCP pipe is established. The server pushes updates strictly when a bed mutation occurs.

Client Connected (Idle 0 bytes)
Staff clicks [+ Vacated ICU]
→ Server broadcasts delta to all sockets in <50ms!

Viva Defense Preparation

Examiner Viva Questions & Model Answers

Q: Why FastAPI over Flask?
FastAPI natively supports asynchronous ASGI and WebSockets out-of-the-box, unlike Flask which requires blocking WSGI workarounds or heavy add-ons.
Q: How do you handle dropped connections?
The client has an auto-reconnect engine with exponential backoff. The server connection manager safely prunes dead sockets to prevent memory leaks.
Q: How do you prevent invalid bed numbers?
Strict Pydantic v2 validation guards prevent negative bed numbers (<0) or numbers exceeding the hospital's registered maximum physical capacity.
Q: How does this scale to 100+ hospitals?
Through horizontal Docker scaling and a Redis Pub/Sub message broker connecting multiple distributed FastAPI nodes.
